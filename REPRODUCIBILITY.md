# Reproducibility Guide

This document describes how to reproduce the paper results using the `main` branch.

> For the exact paper submission code, use: `git checkout paper-submission-2026-03`

---

## Environment

| Requirement | Version | Notes |
|---|---|---|
| Node.js | 22.x (tested on 22.4.1) | ESM modules required |
| npm | 10.x | |
| Docker + Docker Compose | Latest | For containerized execution |
| OS | Linux (Alpine in container) or Windows (host) | |

### API Keys Required

| Key | Provider | Purpose |
|---|---|---|
| `OPENAI_API_KEY` | OpenAI | Primary LLM (GPT-5.1) |
| `GEMINI_API_KEY` | Google | Alternative LLM (optional) |
| `DISCORD_WEBHOOK_URL` | Discord | Notification (optional) |

## Setup

### 1. Clone and checkout

```bash
git clone https://github.com/lxzLocus/gRPC_Analyzer.git
cd gRPC_Analyzer
git checkout main
```

### 2. Install dependencies

```bash
npm install
```

### 3. Configure environment

```bash
cp .env.example .env
# Edit .env and set your API keys
```

### 4. Configure LLM settings

Edit `config/config.json`:

```json
{
  "llm": {
    "provider": "openai",
    "model": "gpt-5.1-chat-latest",
    "maxTokens": 30000,
    "temperature": 0.1,
    "timeout": 60000
  }
}
```

To use Gemini instead, change `provider` to `"gemini"`.

### 5. Build

```bash
npm run build
```

## Dataset

Datasets are located in `dataset/`. Each filtered directory contains repositories with PR data:

```
dataset/
├── raw_cloned/              # Full cloned repositories (source of truth)
├── filtered_protoChanged/   # Proto schema changed PRs
├── filtered_commit/         # Commit-based filtered PRs
├── filtered_fewChanged/     # Few-file-change PRs
├── filtered_confirmed/      # Human-confirmed PRs
└── test/                    # Small test dataset
```

Each PR directory contains:

```
<repo>/<pullrequest|issue>/<pr_number>/
├── premerge/       # Pre-merge source code (symlinked to raw_cloned)
├── 01_protoFile    # Generated: proto file content
├── 02_protoChanges # Generated: proto diff
├── 03_fileChanges  # Generated: changed file paths
├── 04_filePath     # Generated: all file paths
└── 05_targetFiles  # Generated: suspected file contents
```

> Prompt variable files (01–05) are auto-generated by `src/utils/generatePrompt.ts` at runtime.

### Disk Optimization

Use `.docker/link_premerge_sh.sh` to replace `premerge/` directories with symlinks to `raw_cloned/`:

```bash
sh .docker/link_premerge_sh.sh --dry-run    # Preview changes
sh .docker/link_premerge_sh.sh              # Execute (delete + symlink)
sh .docker/link_premerge_sh.sh --verify     # Verify symlinks
```

## Docker Execution

### Using docker-compose

```bash
cd .docker
docker compose up --build grpc-analyzer-node
```

> **Note**: `docker-compose.yml` contains Windows host paths (`E:/Workspace/...`).  
> Adjust the `source:` paths in volume mounts to match your local dataset location.

### Container structure

| Service | Purpose |
|---|---|
| `dev` | Development container |
| `grpc-analyzer-node` | Main execution container |
| `patch-evaluation` | Patch quality evaluation (separate) |

## Evaluation

### Main system (this repository)

The main system (`gRPC_Analyzer`) generates patches and logs in:

- `output/` — Error reports and processing results
- `log/<repo>/` — Per-repository LLM conversation logs

### Patch evaluation (`patchEvaluation/`)

`patchEvaluation/` is an **independent evaluation system** running in a separate Docker container. It reads the logs and output from the main system to evaluate patch quality.

> ⚠️ The evaluation system differs between branches:
>
> | Branch group | Evaluation system |
> |---|---|
> | `baseline/*` | Legacy evaluation |
> | `main`, `fsm-strict/*` | New FSM-based evaluation |

## Troubleshooting

### Common Issues

1. **`ERR_MODULE_NOT_FOUND`**: Run `npm run build` first. All source is TypeScript compiled to `dist/js/`.
2. **API timeout**: Increase `llm.timeout` in `config/config.json` (default: 60000ms).
3. **Missing dataset**: Ensure dataset directories are mounted or present. Check symlinks with `sh .docker/link_premerge_sh.sh --verify`.
4. **Memory issues**: The system includes `MemoryManagementService` for GC. For large datasets, monitor with `performance.enableMonitoring: true` in config.
